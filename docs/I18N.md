# Translating the interface

The GUI is built with Qt6, so its interface can be translated with Qt's own
translation tools. English is the source language: the strings in the code are
the English text, and a catalogue adds other languages. Without a catalogue the
program looks exactly as it always has.

Simplified Chinese (zh_CN) ships in `translations/cheatengine_zh_CN.ts` and is
compiled into the binary. The catalogue is embedded as a resource, so the `.deb`
and the AppImage carry it without extra files.

## Choosing the language

- With no setting, the interface follows the desktop locale (`LANG`, e.g.
  `zh_CN.UTF-8`).
- **Settings > Language** overrides it: follow the system, English, or 简体中文.
  The choice is stored in `ui/language`; when it changes, Cheat Engine offers to
  restart itself so the new language takes effect right away.
- A `.qm` file dropped beside the executable, or under `translations/`, wins over
  the built-in catalogue. That lets a translator try a file without a rebuild.

The Qt standard strings (stock dialog buttons, native file dialogs) come from
Qt's own translations. Linux distributions package those separately
(`qt6-translations-l10n` on Debian/Ubuntu, `qttranslations` on Fedora); install
it for translated standard buttons. The application's own strings work either
way.

## What is translated

Everything the GUI shows: menus, actions, window and tab titles, labels,
buttons, check boxes, tooltips, placeholders, table headers, dialogs, message
boxes, file dialog filters, and the empty-state hints. Numbers, addresses and
values are formatted as before.

Not covered, deliberately:

- `cescan` and other terminal output, which has no interface language.
- Messages produced by the Qt-free `cecore` library (scanner, debugger and
  process errors) are shown as they are, in English.
- The tutorial games (`cetutorial`, `cegtutorial`) keep their English text: the
  tutorial steps describe exact code and instructions in the game.
- Text stored in cheat tables and Lua scripts is user data, never translated.
- Lua and agent tool names are part of the scripting API, never translated.

## For translators

Install the Qt translation tools: `qt6-tools-dev` and `qt6-l10n-tools` on
Debian/Ubuntu. CMake then also builds the catalogues; without them the GUI is
built in English and a status line says so.

Refresh the catalogue from the sources:

```bash
cmake --build build --target update_translations
```

That runs `lupdate` over the GUI sources and merges new strings into the `.ts`
files, keeping existing translations. Translate with Qt Linguist:

```bash
linguist translations/cheatengine_zh_CN.ts
```

or with any editor: the file is plain XML. `cmake --build build` compiles the
catalogue with `lrelease`.

Add a language:

1. Create `translations/cheatengine_<locale>.ts`, e.g. `cheatengine_de.ts`
   (`lupdate` knows the language from the file name).
2. Add it to the `qt_add_translations` call in `CMakeLists.txt`.
3. Add the language to `SettingsDialog::buildLanguagePage` so it can be picked.
4. Update this file and the desktop file / AppStream metadata if the release
   notes should mention it.

Notes for a good translation:

- Keep `%1`, `%2` and `%n` placeholders exactly as they are.
- Keep HTML tags, URLs, and product names (`Cheat Engine`, `Lua`, `ceserver`,
  `GDB`, `QEMU`, `Mono`) as they are.
- Menu items that open a window end in `...`; keep the three dots.
- Top-level menus carry a `&` mnemonic; use `文件(&F)` style.
- The screenshot review can render another language; it reads `CE_LANG`:

  ```bash
  CE_LANG=zh_CN QT_QPA_PLATFORM=offscreen ./build/gui_lifecycle_smoke \
      --screenshots build/i18n-screenshots
  ```

  The review finds windows and menu items by their English source text, so it
  still drives the UI, while every capture is rendered in the chosen language.
